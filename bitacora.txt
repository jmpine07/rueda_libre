Se creo un un formulario dividido en 3 secciones o grupos utilizando el metodo POST.
LOs tres grupos fueron los datos del cliente, datos del alquiler y la confirmación. En los campos se indica el tipo de dato que se debe ingresar y además se colocaron restricciones, para evitar que el cliente o el usuario ingrese datos erroneos o para minimizar la posibilidad de ingresar datos invalidos.
Por eso en tipo de bicicleta se utilizó un select para que el usuario seleccione sólo una de las opciones, al igual que con radio.

Bitácora de validación de herencia CSS (DevTools > Styles y Computed):
- Propiedad que sí hereda: font-family. El body usa 'Open Sans' y el párrafo (p) hereda esa tipografía sin necesidad de definirla en el selector del párrafo.
- Propiedad que no hereda: background-color. El body tiene fondo crema, pero un párrafo no lo hereda automáticamente; en Computed aparece background-color: rgba(0, 0, 0, 0) a menos que se aplique explícitamente a ese elemento o a un contenedor padre del texto.

Bitácora de validación de la clase activo y especificidad:
- Selector original del compañero: `#menu a { color: var(--gris-asfalto); }` tiene especificidad 0,1,1 (1 ID + 1 etiqueta).
- Selector de la clase: `.activo { color: var(--verde-ruta); font-weight: 600; }` tiene especificidad 0,1,0 (1 clase).
- Causa del problema: el selector `#menu a` gana por especificidad aunque la clase esté declarada después, porque una regla con ID tiene más peso que una regla con clase.
- Corrección aplicada: se reemplazó por `#menu a.activo`, que combina ID + clase + etiqueta y pasa a tener especificidad 0,2,1, sin usar `!important` ni estilos en línea.
- Además, se añadieron estados `:hover` y `:focus-visible` para el menú, un botón de llamada a la acción con estilo visual y un indicador de foco visible para inputs, select y textarea.

Bitácora de medición de box-sizing (DevTools > Computed):
- Se tomó como referencia una tarjeta con `width: 24rem; padding: 1.25rem; border: 1px solid`.
- Antes de cambiar `box-sizing`: ancho total calculado = 24rem + 2.5rem + 2px = 426px aprox. (contenido + relleno + borde).
- Después de aplicar `box-sizing: border-box`: ancho total = 384px, manteniendo el mismo ancho visual solicitado y evitando que el relleno y el borde expandan el bloque.
- Resultado: con `border-box`, el espacio visible interno es más estable y el contenedor no se descuadra.

Cuadrícula de flota (Grid + Flexbox):
- La cuadrícula usa `repeat(auto-fit, minmax(220px, 1fr))`, por lo que la cantidad de columnas depende del ancho disponible.
- A 1280 px se observan 4 columnas.
- A 900 px se observan 3 columnas.
- A 500 px se observan 2 columnas.
- La disposición interna de cada tarjeta usa Flexbox para que el botón "Reservar" quede siempre al final, aunque el texto varie en longitud.

Layout general del boceto de Nodo Digital (Grid + Flexbox):
- Portada: se usó Grid con dos columnas (`1.2fr 1fr`) porque el contenido textual y la imagen cumplen roles distintos y deben quedar alineados visualmente con el texto centrado verticalmente.
- Galería de rutas: se usó Grid con tres columnas iguales para mantener una fila con las tres tarjetas y mantener la misma proporción en todas las rutas.
- Reservas: se usó Grid con proporción 2:1 para asignar más espacio al formulario y dejar una columna menor para contacto e información.
- Fila del formulario: se usó Grid para dos campos cortos relacionados (documento y celular), porque exige alineación precisa y un ancho uniforme en la misma fila.
- Encabezado y pie: se usó Flexbox para ubicar marca y menú en extremos, y para distribuir los bloques del footer con alineación vertical y separación uniforme.
- Se ajustó la terminología del proyecto para usar "Ruta" y "Rutas" en vez de "Recorrido" y "Recorridos" para mantener consistencia con el briefing del cliente.

Pruebas responsive mobile-first (360 px, 768 px y 1280 px):
- Problema 1: en 360 px, el encabezado se veía apretado porque el nombre de la marca y el menú estaban en la misma línea. Solución: el bloque del header pasó a ser columna en móvil, con el nombre arriba y el menú debajo, centrados.
- Problema 2: la portada y la galería quedaban demasiado comprimidas en pantallas pequeñas y la imagen se desbordaba del contenedor. Solución: se pasó la portada a una sola columna, se centró el texto y se estableció `max-width: 100%` para todas las imágenes para que nunca superen el ancho disponible.
- Problema 3: la sección de reservas y las tablas de tarifas se volvieron difíciles de leer en móvil. Solución: el layout de reservas pasó a 1 columna y el formulario se ordenó verticalmente; las tablas se redujeron en relleno y tamaño de letra para que no obligaran a desplazarse de lado.
- Problema 4: en resoluciones mayores, el contenido no aprovechaba el espacio disponible. Solución: se activaron media queries a partir de 768 px para recuperar la distribución del MiniReto 1, y a 1200 px se ajustó el ancho máximo de contenido para escritorio.

Conclusión: el sitio queda preparado para móvil, tablet y escritorio con una base mobile-first, mejor legibilidad, contenido ordenado y sin desbordamiento visual.

Prueba de catálogo con Bootstrap 5 (grilla por clases):
- Versión propia: la flota se distribuía con CSS manual en `css/styles.css`, con reglas como `.flota-grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); gap: var(--space-3); }` y la estructura interna de cada tarjeta con Flexbox (`.modelo-card`, `.modelo-card__body`, `.modelo-card__link`). Esta solución exigía de 20 a 30 líneas de CSS de distribución y más control sobre cada detalle.
- Versión Bootstrap: en `pruebas/catalogo-bootstrap.html` la distribución se resuelve solo con clases de grilla: `row g-4`, `col-12`, `col-sm-6`, `col-lg-4`, `col-xl-3`. En otras palabras, la disposición se logra con un conjunto pequeño de clases del sistema, no con reglas propias.
- Lo que Bootstrap da sin esfuerzo: un layout responsivo consistente, gutters automáticos, columnas ajustadas por breakpoint, y una estructura de cards que mantiene la alineación sin escribir media queries ni mantener un grid custom.
- Qué se pierde frente al CSS propio: menos control total sobre el tamaño exacto de cada tarjeta, menos libertad para ajustar márgenes, alturas y comportamientos muy específicos, y más dependencia del sistema de clases del framework.
- Conclusión: Bootstrap resulta muy práctico para prototipos y maquetación rápida, pero el CSS propio sigue siendo más preciso para un proyecto con identidad visual específica y requisitos muy puntuales.

Clases utilitarias de Bootstrap utilizadas en la sección “¿Por qué Rueda Libre?”:
- `text-center`: centra el texto y el contenido dentro de cada tarjeta y del bloque principal.
- `row g-4`: activa el sistema de grilla y aplica separación uniforme entre columnas.
- `col-12 col-md-6 col-xl-3`: define la distribución responsive: una columna en móvil, dos en tablet y cuatro en escritorio.
- `bg-white border border-0 rounded-4 shadow-sm p-4`: crea la tarjeta con fondo blanco, bordes suaves, esquinas redondeadas, sombra ligera y relleno interior.
- `fw-bold text-primary`: jerarquiza el texto destacado del beneficio con peso y color principal de la marca.
- `d-none d-md-block`: oculta la imagen decorativa en celular y la muestra desde tablet en adelante.
- `d-flex flex-column flex-md-row`: organiza la franja final en columna en móvil y en fila desde tablet.
- `justify-content-between align-items-center`: alinea el texto, imagen y botón dentro de la franja final con distribución y centrado visual.
- `btn btn-light text-primary rounded-pill px-4 py-2`: aplica un estilo de enlace destacado usando utilidades de color, relleno y bordes redondeados sin escribir CSS.
